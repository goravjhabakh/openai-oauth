# v1.0 — Stable Language Model Provider

## Goal

Publish `@gorav/openai-oauth` 1.0.0 as a stable Node.js Vercel AI SDK language
model provider. Stability applies to the documented public package contract and
its deliberately narrow, validated OAuth Responses surface—not to OpenAI's
preview Sign in with ChatGPT service, account entitlements, or model catalog.

This release stabilizes existing behavior. It does not add capabilities.

## Stable public contract

- The sole supported import is the ESM root entrypoint, `@gorav/openai-oauth`.
  Runtime exports and declarations must agree for:
  `createOpenAIOAuth`, `OpenAIOAuth`, `FileCredentialStore`,
  `OpenAIOAuthError`, and the documented provider, auth, credential, model,
  capability, and error option types.
- `createOpenAIOAuth(options)` returns a callable provider with
  `provider(modelId)`, `provider.languageModel(modelId)`, and `provider.auth`.
  Its models remain structurally usable as AI SDK `LanguageModelV4` values.
- Required application-owned configuration remains `agentName`, a persistent
  opaque `hostId`, `CredentialStore`, `credentialKey`, and
  `openAuthorizationUrl`. Invalid setup fails locally with actionable
  `OpenAIOAuthError`s.
- Keep the Node.js `>=20` engine, ESM-only packaging, and `ai` `^7.0.0` peer
  range unless compatibility is explicitly revalidated and documented. Do not
  add undocumented subpath exports or require internal/dist imports.
- `OpenAIOAuthError` guarantees redacted `message`, optional `status`, `code`,
  `param`, and `requestId`, plus `retry` of `none`, `backoff`, or
  `reauthorize`. It must not expose tokens, identity claims, authorization URLs,
  request bodies, or tool input.

## Authentication and credentials

- Preserve the documented public OAuth flow: dynamic public-client registration,
  per-attempt PKCE/state/nonce, a `127.0.0.1` `/auth/callback`, issued client ID,
  ID-token validation, and the required direct-plan scope. Never use Codex
  credentials, private routes, a client secret, or fallback billing.
- `signIn()` persists credentials only after callback validation and token
  exchange succeed; `signOut()` revokes the saved refresh token then removes the
  local record. `listModels()` and `listModelCatalog()` require usable
  credentials and expose only the selected account's list-visible models in
  server order.
- Refresh remains on-demand, rotating, and deduplicated per `OpenAIOAuth`
  instance. Terminal refresh failures clear the unusable record; transient
  failures retain it and surface a redacted error.
- The cross-process limitation is a release-blocking documentation and test
  requirement, not a claim of safety: do not share a credential record between
  processes. Consumers needing that topology must use separate records or a
  custom store/coordinator that locks the complete load-refresh-save transaction.
- `FileCredentialStore` is the built-in Node store; consumers own its path,
  record key, permissions, and host-ID persistence. No automatic
  reauthorization, background refresh, keychain integration, or multi-account
  UX is implied.

## Capability and error guarantees

- Every inference request uses the public `/v1/responses` route with
  `store: false` and `stream: true`. `generateText()` aggregates that required
  SSE stream; `streamText()` maps it incrementally. A request succeeds only on
  `response.completed`; failed, incomplete, or premature-EOF streams are not
  successful finishes.
- Text generation and streaming, complete-history function-tool continuation,
  terminal usage/metadata where supplied, and redacted admission/SSE errors are
  supported through normal AI SDK APIs. Unsupported generic AI SDK settings are
  omitted and reported as AI SDK warnings rather than forwarded.
- Model discovery is dynamic and account-aware. A listed model is not an
  entitlement guarantee. Catalog states retain their meanings: `validated` is
  account-backed evidence, `advertised` is route-level documentation, and
  `unknown` is not support.
- The only model-gated features promoted in v1 are those validated for
  `gpt-5.6-terra`: `{ effort: 'medium' }` under
  `providerOptions['openai-oauth']`, top-level client function tools and their
  validated choices/results, strict JSON-schema `Output.object()`, and user
  `image/png` plus `text/plain` URL/inline inputs. All other models and forms
  must remain unknown or fail locally as they do today.
- Preserve the route-wide exclusions: non-streaming HTTP Responses, persistent
  response state, uploads/provider file references, hosted/provider tools,
  web search, audio/video, image generation, file search, Code Interpreter,
  computer use, hosted MCP, and tool search.

## Documentation and examples

- Update the README for a published 1.0.0 package: installation, Node/AI SDK
  requirements, quick start, deliberate sign-in/model discovery/sign-out,
  generation, streaming, errors, and credential protection.
- Keep examples limited to root exports and dynamic model selection. Exact-model
  examples must state the `gpt-5.6-terra` gate and validation boundary.
- Clearly retain the local/open-source preview boundary, hosted/commercial
  caveat, local-browser/loopback requirement, shared ChatGPT-plan usage, and no
  silent alternative billing. Keep project, roadmap, architecture, and research
  aligned with release behavior.

## Publishing and GitHub release readiness

- Before publish, set the release version to `1.0.0`, verify repository/homepage/
  bugs metadata and MIT license, and run `pnpm release-check` from a clean
  checkout. It must type-check, test, build, inspect the tarball, and install,
  type-check, build, and execute the independent offline consumer fixture.
- Inspect the packed tarball: only emitted ESM/declarations, README, license,
  and package metadata may ship. Verify root ESM runtime imports and declaration
  imports from the packed artifact; no source, fixtures, credentials, or
  development artifacts may ship.
- Run `pnpm validate:consumer:live` as an opt-in, sanitized final check with a
  consenting eligible account. It must use only the packed package/root exports,
  complete sign-in, catalog lookup, representative supported AI SDK calls, and
  sign-out without logging sensitive data.
- Publish `@gorav/openai-oauth@1.0.0` publicly using an authorized `@gorav`
  publisher through the protected `Publish to npm` trusted-publishing workflow.
  Confirm the published artifact, automatic provenance, and metadata match the
  inspected tarball. See [`docs/release.md`](../release.md) for the required
  npm/GitHub configuration and manual release procedure.
- Create an annotated `v1.0.0` tag and GitHub Release from that commit. Release
  notes must summarize the stable contract, validated model-gated surface,
  runtime/peer requirements, OAuth-preview caveat, cross-process refresh limit,
  validation gaps, and explicit non-goals. Repository CI runs
  `pnpm release-check`. Publishing proceeds only through the dedicated
  trusted-publishing workflow; GitHub Release creation remains manual.

## Remaining validation gaps

- Account-backed cancellation, interrupted transport, terminal failure/
  incomplete events, and admission error mappings need sanitized live fixtures;
  current coverage is mock/offline for portions of those paths.
- Cross-process rotating-refresh coordination, crash recovery, corrupt records,
  and file-store permission/durability behavior need validation on Windows,
  macOS, and Linux.
- Model catalog behavior and entitlement differences need evidence from another
  account/plan. No result may broaden the public capability matrix without
  account-backed validation.
- These gaps must be disclosed in the README and GitHub Release. They do not
  permit changing success semantics, hiding errors, or representing an
  unvalidated feature as supported.

## Explicit non-goals

- New model capabilities or broader reasoning, tool, structured-output, media,
  file, or tool-result support.
- Browser support; hosted/commercial deployment support; device-code OAuth;
  automatic reauthorization/retries; background refresh; multi-account UX;
  keychain storage; or a cross-process locking redesign.
- Private ChatGPT/Codex endpoints, Codex CLI integration, static/default model
  lists, persistent Responses conversations, billing fallback, or full
  `@ai-sdk/openai` parity.
- Package splitting, undocumented exports, or dependency additions unrelated to
  maintaining this release contract.

## Completion criteria

1. The root public API, generated types, Node/AI SDK compatibility, errors, and
   supported capability matrix have regression coverage from a packed consumer.
2. Offline release checks and the opt-in packed live consumer check pass without
   exposing sensitive data.
3. Documentation, package metadata, tarball contents, npm publication, git tag,
   and GitHub Release describe the same constrained v1.0.0 contract and its
   known gaps.

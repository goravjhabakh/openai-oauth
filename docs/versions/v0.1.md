# v0.1 — Basic OAuth Generation

## Goal

Ship a Node.js-first, single-package vertical slice that lets a local consuming
app sign in with a ChatGPT account and use an entitled, dynamically discovered
model with AI SDK `generateText()`. It must use only the documented public
OpenAI OAuth and Responses API routes; no API key, Codex CLI, or private
ChatGPT backend is involved.

## Scope

- TypeScript package managed with pnpm, using `@ai-sdk/provider` and
  `@ai-sdk/provider-utils`, not `@ai-sdk/openai`.
- A provider factory that produces open-string `LanguageModelV4` model IDs for
  use with `generateText()`.
- An interactive Node authentication helper. It starts the documented
  `127.0.0.1` `/auth/callback` listener, generates per-attempt state, nonce,
  and PKCE S256 material, and passes the authorization URL to an
  application-provided `openAuthorizationUrl(url)` callback. It completes the
  callback, token exchange, ID-token validation, and persistence before
  resolving. The consuming application owns its real `agentName` and stable,
  opaque `hostId`.
- Dynamic OAuth client registration on first sign-in and reuse of the issued
  client ID thereafter. Never persist or exchange `dynamic_agent_client`.
- A built-in Node `FileCredentialStore`, at a path selected by the consuming
  application, with atomic writes and restrictive permissions where supported.
- Access-token refresh before use, serialized per credential record; rotate
  and atomically replace the refresh token record. Support local sign-out and
  token revocation.
- Account-aware model discovery through `GET /v1/models`, retaining only
  `visibility: "list"` records, preserving server order, and using `slug` as
  the model ID.
- Text-only prompt conversion and basic `generateText()` generation. Every
  request sends complete history, `store: false`, and `stream: true`; the
  provider consumes the required Responses SSE stream internally and returns
  the aggregated `doGenerate()` result.
- Basic, non-secret-bearing OAuth, HTTP, admission, and terminal-stream error
  reporting. Preserve status, diagnostic text, error code/parameter, and
  request ID when supplied. Return usage data only when present in the
  terminal response.

## Non-goals

- A public `streamText()` experience or incremental stream parsing; if the
  installed `LanguageModelV4` contract requires `doStream`, it must fail
  explicitly as unsupported rather than imply v0.2 streaming support.
- Tools, reasoning controls, structured output, images/files, and all other
  richer input/output capabilities.
- Persistent Responses conversations, `previous_response_id`, model defaults,
  or a static model list.
- Browser support, device-code authentication, keychain integration, custom
  credential stores, hosted/paid-app authorization workflows, or multi-account
  account-selection UX.
- Full `@ai-sdk/openai` feature parity, a Codex CLI dependency, private
  `chatgpt.com/backend-api` calls, an embedded client secret/API key, or any
  fallback billing source.

## Important interfaces and components

- `OpenAIOAuthAuth` (name may vary): `signIn`, `signOut`, authenticated-token
  retrieval/refresh, and model discovery. `signIn` is the interactive helper
  described above; applications own browser/UI presentation via
  `openAuthorizationUrl`.
- `OAuthCredentials`: issued client ID, host ID, validated identity (`issuer`,
  `sub`, optional email), access/refresh/ID tokens, expiry, scopes, and
  refresh metadata. Secrets must never appear in errors or logs.
- `CredentialStore` remains the internal boundary:
  `load(key)`, `save(key, credentials)`, and `delete(key)`. v0.1 supplies the
  file implementation only; the application chooses the path and record key.
- `FileCredentialStore`: durable, atomic credential replacement and recovery
  from absent/corrupt records; refresh locking protects a record across local
  callers/processes.
- `ResponsesClient`: authenticated public `GET /v1/models` and mandatory-SSE
  `POST /v1/responses` requests.
- Provider/model adapter: prompt conversion, unsupported-setting warnings,
  SSE aggregation, terminal completion validation, usage/finish mapping, and
  `LanguageModelV4GenerateResult` construction.

## Implementation order

1. Create the package/tooling and pin the inspected AI SDK provider versions;
   verify the exact `LanguageModelV4` contract and utility exports.
2. Define credential types, file-store durability/locking behavior, redaction,
   and auth error types.
3. Implement the documented dynamic-client PKCE loopback sign-in, OIDC
   discovery/JWKS validation, persistence, refresh rotation, and revocation.
4. Implement authenticated model discovery and its public account-aware API.
5. Implement the minimal Responses client and capture its SSE parser/terminal
   result independently of AI SDK conversion.
6. Implement text prompt conversion and the `LanguageModelV4` `doGenerate()`
   SSE aggregation path; omit unsupported options and surface warnings.
7. Add package documentation and a local-only example that states the preview,
   plan-sharing, and downstream hosted/commercial-use boundary.

## Required validation before relying on behavior

With a consenting test account, capture sanitized fixtures and request IDs
(never tokens or personal data) for:

1. Dynamic registration, callback fields, scopes, token fields,
   `earliest_refresh_at`, and ID-token/JWKS validation—including negative
   state, nonce, issuer, audience, signature, and expiry cases.
2. Reauthorization with the issued client ID, account/workspace binding, and
   refresh rotation. Test concurrent refresh under the selected lock and every
   terminal refresh failure policy.
3. `/v1/models` responses for at least two account/plan types, including
   visibility, order, schema, and account-switch changes.
4. Minimal text generation with only the required fields; record the complete
   SSE sequence, terminal response, usage, headers, and interruption behavior.
5. AI SDK `generateText()` aggregation semantics: text, finish reason, usage,
   cancellation, pre-stream errors, terminal failures, and EOF before
   `response.completed`.
6. System/developer prompt mapping and representative unsupported generic
   settings. Confirm each is either safely omitted with a warning or rejected;
   never forward known unsupported fields.
7. File-store crash recovery, corrupt records, permissions, atomic replacement,
   and cross-process locking on Windows, macOS, and Linux.

These experiments are release gates, not optional compatibility polish. Any
protocol result that conflicts with the research record must be documented in
`docs/research.md` before the implementation depends on it.

## Testing expectations

- Unit tests for PKCE/state construction, OAuth callback validation, OIDC claim
  validation, refresh scheduling/rotation, credential redaction, file-store
  atomicity, locking, model filtering, prompt conversion, SSE parsing, and
  terminal-result aggregation.
- Mocked HTTP integration tests for first and later authorization, refresh,
  revocation, discovery, all required Responses terminal/error paths, and
  `generateText()` output/warnings/errors.
- Fixture tests must be sanitized, deterministic, and cover malformed SSE and
  a stream that ends without `response.completed`.
- Manual account-backed validation must execute every experiment above before
  publish; no live credentials, authorization URLs containing hints, or
  personal data may be committed.

## Completion criteria

v0.1 is complete when a local Node app can supply its app/host identity and
credential path, complete documented sign-in, discover its visible models, and
call `generateText()` with text input through a selected model. It receives a
correct aggregated result or a actionable, redacted error; tokens refresh and
sign-out/revocation work; the required validation fixtures and tests pass; and
documentation clearly limits the release to preview, local OAuth-backed basic
generation.

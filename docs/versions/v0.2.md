# v0.2 — Streaming

## Goal

Expose the existing OAuth-backed, mandatory Responses SSE request as a normal AI
SDK `streamText()` experience. Text must arrive incrementally through
`LanguageModelV4.doStream()` while preserving v0.1's public API, prompt
conversion, OAuth refresh, public `/v1/responses` route, and `store: false` /
`stream: true` request requirements.

## Included scope

- Implement `doStream(options)` on `OpenAIOAuthLanguageModel` and support
  text-only `streamText()` calls.
- Parse the Responses SSE body incrementally, including events split across
  network chunks, and translate supported events to AI SDK v4 stream parts:
  `stream-start`, text start/delta/end, response metadata when available, and
  terminal `finish`.
- Continue to send the v0.1 request shape and unsupported-setting warnings.
- Map the terminal completed response's status and usage to the AI SDK finish
  reason and usage shape. Preserve the raw usage object when present; do not
  invent usage when it is absent.
- Propagate the caller's `AbortSignal` to `fetch` and promptly cancel reading
  the response body when the consumer cancels the returned stream.
- Preserve v0.1's actionable, redacted HTTP and SSE error information,
  including status/diagnostic text, code, parameter, and request ID where
  supplied.

## Explicit non-goals

- Tools, tool-call deltas, reasoning, citations, structured output, rich
  inputs, raw chunk exposure, persistent response state, or model discovery
  changes.
- Changing `doGenerate()` aggregation behavior or adding retries/fallbacks.
- Browser support, private ChatGPT/Codex routes, API-key billing, or OAuth
  lifecycle changes.
- Claiming support for event types or metadata fields not verified by a
  sanitized account-backed fixture.

## Implementation order

1. Re-check the installed AI SDK `LanguageModelV4` stream contract and capture
   a sanitized complete Responses SSE fixture, including headers, terminal
   response, usage, cancellation, and failure cases.
2. Separate the Responses client's authenticated request opening and
   incremental SSE iteration from v0.1's aggregation-only `generate()` path;
   retain the existing parser's split-event and malformed-JSON handling.
3. Add a narrow Responses-event-to-`LanguageModelV4StreamPart` mapper for
   text and terminal state. Emit `stream-start` with existing warnings, use a
   stable per-output text ID, and emit `finish` only after
   `response.completed`.
4. Implement `doStream()` with a `ReadableStream`, request body, and response
   headers. Wire both the call abort signal and stream cancellation to the
   upstream fetch/body reader.
5. Define and test the failure boundary: pre-stream admission failures reject
   `doStream()`; failures observed after the stream begins produce an AI SDK
   `error` part and terminate without a successful `finish`; EOF before
   `response.completed` is likewise an error.
6. Refactor only where shared parsing/mapping avoids divergent v0.1
   `doGenerate()` and v0.2 behavior; keep the public factory surface unchanged.

## Important interfaces/components

- **`OpenAIOAuthLanguageModel.doStream`**: builds the same supported request
  as `doGenerate()` and returns `LanguageModelV4StreamResult`.
- **`ResponsesClient`**: opens authenticated SSE responses, exposes headers
  and a cancelable incremental event iterator, and normalizes admission,
  malformed-SSE, terminal-failure, and premature-EOF errors without exposing
  secrets.
- **SSE parser and event mapper**: preserves event ordering; maps
  `response.output_text.delta` to text deltas and derives response ID/model/
  timestamp metadata only from received response objects. `response.completed`
  is the sole success terminal event. `response.failed`,
  `response.incomplete`, `error`, transport failure, and premature EOF are
  unsuccessful.
- **Usage/finish mapper**: uses the terminal response's input, cached-input,
  output, and reasoning-token fields when present, matching v0.1's usage
  semantics and finish-reason mapping.
- **Cancellation bridge**: connects AI SDK call cancellation and downstream
  `ReadableStream.cancel()` to the active fetch/body reader exactly once; an
  intentional caller cancellation must not be reported as a successful finish.

## Validation and testing

- Unit-test SSE parsing across arbitrary chunk boundaries, multiline data,
  `[DONE]`, malformed JSON, and a final unterminated event.
- Fixture-test stream-part order and contents for text deltas, metadata,
  terminal usage/finish reason, missing usage, `failed`, `incomplete`, `error`,
  transport failure, and EOF before completion.
- Mocked integration-test `streamText()` consumption for incremental text,
  warnings, response headers/ID, usage, and each error boundary. Verify
  `generateText()` continues to pass unchanged.
- Test abort before a response, abort while awaiting a chunk, and consumer
  cancellation after one delta. Assert that the fetch signal/body reader is
  cancelled and that no completed finish is emitted.
- Before release, perform consenting account-backed validation and save only
  sanitized fixtures/request IDs. Confirm the actual event sequence, terminal
  usage/metadata, cancellation behavior, terminal failures, and interrupted
  streams; record any changed protocol facts in `docs/research.md`. Prefer the
  account's `gpt-5.6-terra` model for these checks. This release does not
  forward reasoning controls, so do not send the separate medium-effort test
  preference until that capability is implemented and verified.

## Completion criteria

v0.2 is complete when a signed-in local Node application can call
`streamText()` with v0.1-supported text input and receive ordered incremental
text plus accurate terminal finish, usage, and available response metadata.
Cancellation stops upstream work, non-success terminals and premature EOF are
not reported as success, and admission/stream errors remain actionable and
redacted. The specified unit, mocked integration, and sanitized live-validation
coverage passes without expanding v0.1's capability surface.

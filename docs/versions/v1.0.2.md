# v1.0.2 — Host ID Validation and Consumer Validation Follow-up

## Goal

Ship a small patch that improves OAuth configuration validation discovered during testing of the published package in a fresh AI SDK consumer project.

This release does not add provider capabilities.

**Status:** Implementation and release validation are complete. npm publication
and tag creation remain deliberate manual release steps.

## Changes

### Validate `hostId` locally

`createOpenAIOAuth()` currently accepts any non-empty `hostId`, which allows a bare UUID such as:

```text
e18da6f1-9b2f-4f88-9950-2d202c32bd24
```

OpenAI's Sign in with ChatGPT flow expects supported host-ID formats such as:

```text
urn:uuid:e18da6f1-9b2f-4f88-9950-2d202c32bd24
```

or the recommended JWK-thumbprint URN form.

For v1.0.2:

- Accept supported `urn:uuid:<uuid>` host IDs.
- Accept `urn:ietf:params:oauth:jwk-thumbprint:<value>` host IDs.
- Reject malformed or bare UUID host IDs locally.
- Throw an actionable `OpenAIOAuthError` before opening the browser.
- Keep the requirement that the consuming application owns and persists the host ID.

### Documentation

- Update README examples to use a valid persisted host ID.
- Explicitly document that UUID host IDs must use the `urn:uuid:` prefix.
- Keep JWK-thumbprint URNs documented as the recommended format where appropriate.

### Regression coverage

Add tests for:

- valid `urn:uuid:` host ID
- valid JWK-thumbprint URN host ID
- bare UUID rejection
- malformed host ID rejection
- existing option validation behavior

## External AI SDK validation — Complete

The published package has already passed a fresh-consumer test for:

- OAuth sign-in
- dynamic model discovery
- `generateText()`
- `streamText()`
- medium reasoning on `gpt-5.6-terra`
- function tool calling and continuation
- `Output.object()` structured output
- valid inline PNG input using known-valid image bytes
- inline `text/plain` input
- sign-out

The earlier inline-PNG rejection was caused by invalid test image bytes. A
known-valid PNG completed successfully, so no provider image-handling change was
needed.
